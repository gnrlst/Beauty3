# B3 учёт — HairFlow v0.3

Система управленческого учёта волос с облачной базой Cloudflare D1 и авторизацией ChatGPT через Sites.

## Что работает

Закупки с историческим валютным курсом, приёмка и индивидуальные номера, обработка с потерями веса и себестоимостью, складские перемещения, продажа партнёру, отдельные партнёрские пространства, продажи части волос, оплаты продаж, полные возвраты, доли положительной и отрицательной маржи, Code 128 и печать этикеток, серверные CSV-выгрузки, журнал действий и управление ролями сотрудников.

## Интерфейс

Приложение служит для простого сбора данных. На главном экране — доступные по роли действия: принять волосы, записать обработку, переместить, записать продажу. Основные разделы: Работа, Волосы, Продажи (последний только для ролей с продажами, оплатами или финансовым доступом). Партнёры, сотрудники и настройки находятся в Управлении. Карточки волос показывают вес, характеристики и действия; происхождение, история и штрихкод раскрываются по нажатию. Дополнительные характеристики закупки и расходы скрыты в раскрываемой секции; обязательные поля и автоматические расчёты сохранены.

Графики, финансовая сводка, отдельная аналитика и встроенный имитационный помощник удалены из интерфейса. Сервер по-прежнему рассчитывает себестоимость, потери и доли. Анализ через виртуального B3 accounter в Telegram — следующий этап, интеграции пока нет. Данные, права, API, аудит и резервные копии сохранены. Суммы и вес новой закупки/продажи не заполняются демонстрационными значениями. Интерфейс адаптирован под телефон и компьютер.

## Авторизация и сотрудники

Руководитель активируется при первом входе с email владельца, который хранится только в серверной переменной OWNER_EMAIL. После входа учётная запись привязывается к устойчивому идентификатору пользователя этого сайта.

Руководитель добавляет сотрудника по email и назначает роль в выбранной компании. Сотрудник входит через ChatGPT с этим email. Доступ к закрытому сайту дополнительно предоставляется через его настройки общего доступа. Добавление роли в приложении не отправляет приглашений и не меняет аудиторию сайта.

Главная компания может наблюдать переданные ей волосы у партнёров и управлять назначением партнёрских сотрудников. Остальные товары партнёра скрыты. Для работы в партнёрской компании нужна отдельная роль этой компании.

## Данные

Учётные документы, остатки и расчёты хранятся в транзакционном реестре business_state в D1. Пользователи и журнал аудита находятся в отдельных реляционных таблицах members и audit. Изменения реестра используют версию и атомарную проверку конкурентной записи. API рассчитывает себестоимость самостоятельно и не принимает готовые суммы прибыли из браузера. Скрытые поля удаляются сервером из ответа. Сервер проверяет компанию и роль для каждого чтения, изменения и экспорта.

Новая облачная база создаётся пустой: старые браузерные демонстрационные записи автоматически не переносятся. Примеры E.seed используются только для тестов. Telegram и голос не подключены.

## Ограничения текущей версии

Ещё не реализованы пригодный вычёс как отдельный товар, разделение и объединение хвостов, частичные возвраты, отдельные оплаты закупок, партнёрские выплаты, общие расходы и банковские счета. Возврат после последующей обработки требует отдельной оценки и блокируется. Учёт пока использует единую версию реестра; для крупного объёма требуется выделение документов в самостоятельные таблицы.

## Разработка

Node 22.13 или новее. Установить зависимости: npm ci. Миграции: npm run db:generate. Сборка: npm run build. В Sites следовать его процедуре установки, сборки и публикации. Хостинг автоматически применяет миграции из drizzle перед публикацией. Конфигурация ресурса D1: .openai/hosting.json. Не хранить email владельца, токены и реальные данные в исходном коде.

Проверки: node tests/engine.test.cjs; node tests/permissions.test.cjs; node tests/database.test.cjs; node tests/render.test.cjs; node tests/forms.test.cjs; node tests/backups.test.cjs; npx tsc --noEmit. Проверки рендера и форм выполняются без полноценного браузера; визуальная браузерная проверка в текущей среде недоступна.

## Резервные копии

Добавлены серверные ежедневные копии D1 в отдельное R2, хранение 30 дней, SHA-256 и обязательная проверка чтением, ручное создание и скачивание владельцем в настройках. Облачное расписание Sites работает без открытой страницы. Инструкции запуска и восстановления: [BACKUPS.md](BACKUPS.md). Восстановление образца в SQLite проверено; это не автоматическое восстановление живой базы. Для защиты от удаления проекта нужна скачанная копия вне Sites.
