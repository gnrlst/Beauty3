# B3 учёт — HairFlow v0.4

Система управленческого учёта волос с облачной базой Cloudflare D1 и авторизацией ChatGPT через Sites.

## Что работает

Закупки с историческим валютным курсом, приёмка и индивидуальные номера, обработка с потерями веса и себестоимостью, складские перемещения, продажа партнёру, отдельные партнёрские пространства, продажи части волос, оплаты продаж, полные возвраты, доли положительной и отрицательной маржи, Code 128 и печать этикеток, серверные CSV-выгрузки, журнал действий и управление ролями сотрудников.

## Интерфейс и отделы

Главная — простой экран с карточками разделов: Поставки, Склад, Производство, Магазин. Сотруднику показываются разрешённые разделы, владельцу доступны все. В Поставках — поступления; на Складе — остатки и перемещения; в Производстве — обработка и отправка готовых волос; в Магазине — остатки, продажи, оплаты и возвраты. Управление сотрудниками, партнёрами и настройками находится отдельно. Графиков, финансовой сводки и общего журнала в пользовательском интерфейсе нет.

Роли: Менеджер поставок, Менеджер склада, Менеджер производства, Менеджер магазина, Бухгалтер, Руководитель, Партнёр. Один отдел может иметь несколько сотрудников. Старые названия ролей совместимы. Склад, производство и магазин имеют серверную фильтрацию по месту хранения; действия с волосами другого отдела отклоняются сервером. Закупщик видит поставки своей компании; бухгалтер может работать с поставками и оплатами. Руководитель компании видит все её отделы; владелец главной компании также наблюдает за её волосами у партнёров. Посторонние поставки партнёра скрыты.

Цена и вес не заполняются демонстрационными значениями. Сервер продолжает считать себестоимость, потери и доли; анализ через B3 accounter в Telegram — следующий этап, интеграции пока нет.

## Постоянное скрытое логирование

Журнал хранится в таблице audit в D1 и попадает в ежедневные резервные копии. Это постоянные записи приложения, а не память ассистента. Каждая проведённая учётная операция атомарно сохраняется вместе с аудитом: автор, время, компания, объект, входные данные, состояние до/после и версии реестра. Также фиксируются ошибки и повторные запросы, создание/изменение/отзыв доступа, первая привязка учётной записи, выгрузки CSV, создание/проверка/скачивание копий базы. API чтения журнала разрешён только владельцу главной компании; кнопки и таблицы журнала убраны из интерфейса.

Просмотры разделов и карточек, открытие/отмена форм, поиск, фильтры, раскрытие деталей, переключение компании и запрос печати этикетки отправляются отдельными событиями /api/activity. Автор и дата задаются сервером, компания/объекты/раздел проверяются по правам. Повторная отправка с тем же ID не создаёт дубль. Эти браузерные события не заменяют транзакционный аудит; при обрыве связи или закрытии браузера до отправки диагностическое событие может не дойти. Клавиатурные нажатия и секреты входа не записываются. Старые записи до расширения логирования не дополняются вымышленными значениями до/после.

## Авторизация и сотрудники

Руководитель активируется при первом входе с email владельца, который хранится только в серверной переменной OWNER_EMAIL. После входа учётная запись привязывается к устойчивому идентификатору пользователя этого сайта.

Руководитель добавляет сотрудника по email и назначает роль в выбранной компании. Сотрудник входит через ChatGPT с этим email. Доступ к закрытому сайту дополнительно предоставляется через его настройки общего доступа. Добавление роли в приложении не отправляет приглашений и не меняет аудиторию сайта.

Главная компания может наблюдать переданные ей волосы у партнёров и управлять назначением партнёрских сотрудников. Остальные товары партнёра скрыты. Для работы в партнёрской компании нужна отдельная роль этой компании.

## Данные

Учётные документы, остатки и расчёты хранятся в транзакционном реестре business_state в D1. Пользователи и журнал аудита находятся в отдельных реляционных таблицах members и audit. Изменения реестра используют версию и атомарную проверку конкурентной записи. API рассчитывает себестоимость самостоятельно и не принимает готовые суммы прибыли из браузера. Скрытые поля удаляются сервером из ответа. Сервер проверяет компанию и роль для каждого чтения, изменения и экспорта.

Новая облачная база создаётся пустой: старые браузерные демонстрационные записи автоматически не переносятся. Примеры E.seed используются только для тестов. Telegram и голос не подключены.

## Ограничения текущей версии

Ещё не реализованы пригодный вычёс как отдельный товар, разделение и объединение хвостов, частичные возвраты, отдельные оплаты закупок, партнёрские выплаты, общие расходы и банковские счета. Возврат после последующей обработки требует отдельной оценки и блокируется. Учёт пока использует единую версию реестра; для крупного объёма требуется выделение документов в самостоятельные таблицы.

## Разработка

Node 22.13 или новее. Установить зависимости: npm ci. Миграции: npm run db:generate. Сборка: npm run build. В Sites следовать его процедуре установки, сборки и публикации. Хостинг автоматически применяет миграции из drizzle перед публикацией. Конфигурация ресурса D1: .openai/hosting.json. Не хранить email владельца, токены и реальные данные в исходном коде.

Проверки: node tests/engine.test.cjs; node tests/permissions.test.cjs; node tests/database.test.cjs; node tests/render.test.cjs; node tests/forms.test.cjs; node tests/departments-audit.test.cjs; node tests/backups.test.cjs; npx tsc --noEmit. Проверки рендера и форм выполняются без полноценного браузера; визуальная браузерная проверка в текущей среде недоступна.

## Резервные копии

Добавлены серверные ежедневные копии D1 в отдельное R2, хранение 30 дней, SHA-256 и обязательная проверка чтением, ручное создание и скачивание владельцем в настройках. Облачное расписание Sites работает без открытой страницы. Инструкции запуска и восстановления: [BACKUPS.md](BACKUPS.md). Восстановление образца в SQLite проверено; это не автоматическое восстановление живой базы. Для защиты от удаления проекта нужна скачанная копия вне Sites.


### Мобильный интерфейс
Нижняя навигация на телефоне, четыре карточки отделов, формы в одну колонку на весь экран, закреплённые кнопки действий, цифровая клавиатура для чисел. Поддерживаются безопасные отступы экранов, увеличение масштаба и навигация с клавиатуры. Графики и журнал скрыты.


### Оформление B3
Редакционная типографика и палитра фарфора, бордо, шалфея и графита. Главная с цветными карточками отделов, контрастные операции и формы. Шрифты с кириллицей размещены локально в public/fonts, лицензия OFL включена. Размеры элементов и навигация адаптированы к телефонам.
